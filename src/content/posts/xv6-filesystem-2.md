## 一、实验整体内容

本实验为MIT 6.828操作系统课程的文件系统综合实验，包含两个独立子实验：Large Files（大文件支持）与Symbolic Links（符号链接实现）。两个子实验分别从文件系统的磁盘存储扩展、文件类型与语义扩展两个维度，对xv6文件系统进行功能增强：

1. **Large Files子实验**：修改inode的多级索引结构，新增二级间接块支持，突破原生文件最大大小限制，支持更大尺寸的普通文件。
2. **Symbolic Links子实验**：新增符号链接文件类型，修改文件打开逻辑实现自动跟随跳转，支持`O_NOFOLLOW`标志位，并实现循环链接防御机制。

## 二、子实验一：Large Files（大文件支持）

### 2.1 实验内容

原生xv6文件系统的inode仅支持12个直接数据块与1个一级间接块，单文件最大尺寸仅为268KB，无法满足大文件存储需求。本实验的核心任务是修改inode的磁盘结构与块映射逻辑，新增二级间接块（双间接块）支持，在不扩大inode地址数组总大小的前提下，大幅提升单文件的最大存储容量。

### 2.2 实验源码分析

#### 2.2.1 原生inode磁盘结构

xv6的磁盘inode（`struct dinode`）定义在`kernel/fs.h`中，核心的地址映射数组`addrs`共13项：

- 前12项为直接块指针，直接存储数据块的物理块号，小文件可直接访问，无额外磁盘IO
- 第13项为一级间接块指针，指向一个专门的间接块，间接块中存储256个数据块号（块大小1024字节，每个块号占4字节） 原生单文件最大块数：12 + 256 = 268块，对应大小268KB。

#### 2.2.2 核心依赖函数

1. `bmap(struct inode *ip, uint bn)`：块映射函数，负责将文件的逻辑块号转换为磁盘物理块号；若对应块尚未分配，则申请新的磁盘块并建立映射关系，是文件读写的核心底层函数。
2. `itrunc(struct inode *ip)`：文件截断函数，负责释放文件占用的所有数据块与间接块，回收磁盘空间，与`bmap`的分配逻辑一一对应。
3. `balloc(int dev)`：磁盘块分配函数，从磁盘空闲块位图中申请一个空闲数据块。
4. `brelse(struct buf *b)`：缓冲区释放函数，释放磁盘块对应的内核缓冲区。

#### 2.2.3 原生bmap执行流程

原生`bmap`仅支持直接块与一级间接块，执行逻辑为：

1. 若逻辑块号小于直接块数量，直接返回对应直接块号，无对应块则分配新块
2. 否则处理一级间接块：若无间接块则先分配间接块，再读取间接块内容，查找对应偏移的块号，无块则分配新块并写入间接块

### 2.3 实验相关知识解读

#### 2.3.1 多级索引文件结构

文件系统采用多级索引结构管理文件数据块，平衡小文件性能与大文件容量：

- 直接块：小文件可直接通过inode获取块号，访问速度最快，无额外磁盘IO
- 一级间接块：通过一次间接跳转获取块号，适合中等大小文件
- 二级间接块：通过两次间接跳转获取块号，支持大文件存储，但访问需要额外两次磁盘IO 多级索引的设计思想是用少量间接块的开销，换取极大的文件容量扩展。

#### 2.3.2 磁盘块与间接块容量计算

xv6磁盘块大小为1024字节，每个块号为4字节的uint32整数，因此单个间接块最多可存储 `1024 / 4 = 256` 个块号。 新增二级间接块后，单文件最大块数为： 11个直接块 + 256个一级间接块 + 256×256个二级间接数据块 = 65803块，对应最大文件大小约64MB，提升约245倍。

#### 2.3.3 文件截断的资源回收

文件截断操作必须完整释放所有层级的块资源，包括数据块、一级间接块、二级间接块，若释放不彻底会造成磁盘块泄漏，浪费磁盘空间。回收顺序必须自底向上：先释放最底层的数据块，再释放间接块本身，避免释放后指针悬空。

### 2.4 实验任务解决思路及实际代码变更

#### 2.4.1 整体解决思路

在不改变inode地址数组总长度的前提下，减少1个直接块，腾出位置新增二级间接块指针；同步修改`bmap`函数增加二级间接块的映射与分配逻辑，修改`itrunc`函数增加二级间接块的回收逻辑，保证分配与回收完全对应。

#### 2.4.2 详细设计思路

1. **结构调整**：将直接块数量`NDIRECT`从12修改为11，inode地址数组保留13项，其中前11项为直接块，第12项为一级间接块，第13项为二级间接块，保持磁盘inode大小不变。
2. **bmap逻辑扩展**：
   - 逻辑块号小于11：走直接块逻辑
   - 逻辑块号减去11后小于256：走一级间接块逻辑
   - 剩余块号走二级间接块逻辑：先检查二级间接块是否存在，不存在则分配；读取二级间接块内容，根据块号偏移找到对应的一级间接块项，不存在则分配一级间接块；再读取一级间接块内容，找到对应数据块项，不存在则分配数据块
3. **itrunc逻辑扩展**：
   - 先释放二级间接块层级：遍历二级间接块中的所有一级间接块项，逐个释放其指向的数据块，再释放一级间接块本身；全部释放完成后，释放二级间接块本身
   - 再释放一级间接块与直接块
4. **边界校验**：所有块号计算都做范围校验，超出最大文件块数则返回错误，避免越界访问。

#### 2.4.3 实际代码变更

##### （1）修改kernel/fs.h宏定义

```c
// 修改前
#define NDIRECT 12
#define NINDIRECT (BSIZE / sizeof(uint))
#define MAXFILE (NDIRECT + NINDIRECT)

// 修改后
#define NDIRECT 11
#define NINDIRECT (BSIZE / sizeof(uint))
#define MAXFILE (NDIRECT + NINDIRECT + NINDIRECT * NINDIRECT)
```

`struct dinode`与内存inode的`addrs`数组长度对应调整为`NDIRECT + 2`，覆盖直接块、一级间接块、二级间接块三类指针。

##### （2）修改kernel/fs.c中bmap函数，新增二级间接块处理

在原生直接块、一级间接块处理逻辑之后，新增二级间接块分支：

```c
bn -= NDIRECT + NINDIRECT;
if(bn < NINDIRECT * NINDIRECT){
    // 分配二级间接块本体
    if(ip->addrs[NDIRECT + 1] == 0)
        ip->addrs[NDIRECT + 1] = balloc(ip->dev);
    bp = bread(ip->dev, ip->addrs[NDIRECT + 1]);
    a = (uint*)bp->data;

    // 计算两级间接索引
    int idx1 = bn / NINDIRECT;
    int idx2 = bn % NINDIRECT;

    // 分配对应一级间接块
    if(a[idx1] == 0)
        a[idx1] = balloc(ip->dev);
    struct buf *bp2 = bread(ip->dev, a[idx1]);
    uint *a2 = (uint*)bp2->data;

    // 分配最终数据块
    if(a2[idx2] == 0)
        a2[idx2] = balloc(ip->dev);
    addr = a2[idx2];

    brelse(bp2);
    brelse(bp);
}
```

##### （3）修改kernel/fs.c中itrunc函数，新增二级间接块回收

在原生一级间接块释放逻辑之前，新增二级间接块的逐层回收：

```c
// 释放二级间接块层级
if(ip->addrs[NDIRECT + 1]){
    bp = bread(ip->dev, ip->addrs[NDIRECT + 1]);
    a = (uint*)bp->data;
    for(i = 0; i < NINDIRECT; i++){
        if(a[i]){
            // 释放每个一级间接块下的所有数据块
            struct buf *bp2 = bread(ip->dev, a[i]);
            uint *a2 = (uint*)bp2->data;
            for(int j = 0; j < NINDIRECT; j++){
                if(a2[j])
                    bfree(ip->dev, a2[j]);
            }
            brelse(bp2);
            bfree(ip->dev, a[i]);
        }
    }
    brelse(bp);
    bfree(ip->dev, ip->addrs[NDIRECT + 1]);
    ip->addrs[NDIRECT + 1] = 0;
}
```

## 三、子实验二：Symbolic Links（符号链接实现）

### 3.1 实验内容

本实验在xv6现有文件系统框架下完成符号链接（软链接）的打开支持功能开发。核心任务为修改内核中`sys_open`系统调用的实现，使其具备三项核心能力：

1. 打开符号链接文件时，自动读取链接存储的目标路径，最终打开目标文件，实现符号链接自动跟随
2. 支持标准`O_NOFOLLOW`标志位，携带该标志打开文件时，若路径最终分量为符号链接则不跟随跳转
3. 实现多层嵌套符号链接解析，并通过深度阈值限制防御循环符号链接，避免内核陷入无限循环

### 3.2 实验源码分析

#### 3.2.1 原生sys_open执行流程

原生xv6的`sys_open`函数定义在`kernel/sysfile.c`中，是文件打开操作的内核入口，原生执行流程如下：

1. 从用户栈中解析获取路径字符串参数与文件打开模式参数
2. 调用`begin_op()`开启文件系统日志事务，保证文件操作的崩溃一致性
3. 根据打开模式分支处理：
   - 若携带`O_CREATE`标志：调用`create()`函数创建新文件，直接返回加锁后的目标inode
   - 若无`O_CREATE`标志：调用`namei()`解析路径获取对应inode，再调用`ilock()`对inode加锁
4. 执行文件类型合法性校验：目录类型仅允许只读打开，设备文件校验主设备号范围合法性
5. 调用`filealloc()`分配内核文件结构体`struct file`，调用`fdalloc()`为进程分配文件描述符
6. 初始化文件结构体：设置文件类型、读写权限、文件偏移量，关联inode指针
7. 若携带`O_TRUNC`标志且为普通文件，调用`itrunc()`截断文件内容
8. 调用`iunlock()`释放inode锁，调用`end_op()`结束日志事务，返回文件描述符

原生xv6未定义符号链接文件类型，也无对应解析逻辑，若磁盘上存在符号链接文件，原生代码会将其当作普通文件处理，无法完成路径跳转，不符合符号链接的语义要求。

#### 3.2.2 核心依赖函数与数据结构

1. `namei(const char *path)`：路径解析函数，根据输入的路径字符串查找对应文件的inode，返回的inode引用计数已+1，但未持有锁。
2. `ilock(struct inode *ip)`：inode加锁函数，获取inode的自旋锁，保证多核并发场景下inode元数据与数据块操作的原子性。
3. `iunlockput(struct inode *ip)`：同时完成inode解锁与引用计数递减，用于释放不再使用的inode资源。
4. `readi(struct inode *ip, int user_src, uint64 dst, uint off, uint n)`：inode数据读取函数，从inode对应的数据块中读取n字节数据到目标地址；`user_src`为0表示目标地址是内核空间地址，为1表示用户空间地址。
5. `struct inode`：内核inode结构体，核心字段包括`type`（文件类型）、`size`（文件字节大小）、`major`（主设备号）等。

### 3.3 实验相关知识解读

#### 3.3.1 符号链接基本概念

符号链接又称软链接，是一种特殊类型的文件，其文件数据块中存储的不是业务数据，而是另一个文件的路径字符串。操作系统打开符号链接时，会自动读取其中的路径字符串并解析，最终打开路径指向的目标文件。与硬链接不同，符号链接可以跨文件系统创建、可以指向目录，目标文件被删除后符号链接会失效（悬空链接）。

#### 3.3.2 O_NOFOLLOW标志语义

`O_NOFOLLOW`是POSIX标准定义的open系统调用标志位。当调用方携带该标志打开文件时，若路径的最后一个分量是符号链接，内核不会跟随链接跳转，直接返回打开失败。该标志主要用于防范符号链接攻击，确保操作的对象是链接文件本身而非跳转后的目标。

#### 3.3.3 xv6 inode锁与引用计数机制

xv6中每个inode通过两个维度管理生命周期与并发安全：

- **自旋锁**：保护inode元数据与数据块的并发访问，任何读取或修改inode内容的操作都必须先持有锁，避免多核场景下的数据竞争。
- **引用计数**：记录当前内核中指向该inode的指针数量，每新增一个引用计数加1，释放时计数减1，计数归零时内核回收该inode。 `iunlockput`函数会同时执行解锁和引用计数递减操作，必须与加锁操作严格成对使用，否则会出现锁泄露、内存泄漏或内核死锁。

#### 3.3.4 嵌套符号链接与循环防护

符号链接的目标可以是另一个符号链接，形成多层嵌套的链接链，内核需要逐层解析直到找到真实文件。若用户构造双向指向的符号链接，会形成解析循环，无限制的解析会导致内核陷入无限循环，永久占用CPU资源，因此必须设置最大解析深度，超过阈值则终止解析并返回错误。

### 3.4 实验任务解决思路及实际代码变更

#### 3.4.1 整体解题流程

本次子实验按照「需求拆解→原生代码缺口定位→核心逻辑设计→编译错误修复→结构性缺陷修复→全路径资源一致性校验」的步骤逐步推进，所有修改均在原生`sys_open`的现有框架上补充，不改动文件系统底层其他模块，确保不破坏原有文件打开逻辑。

#### 3.4.2 需求拆解与实现位置定位

将实验要求拆解为三个可落地的实现点：

1. 自动跟随：识别符号链接类型的inode，读取其存储的目标路径，替换当前inode为目标文件的inode
2. 标志控制：通过`O_NOFOLLOW`标志位控制是否触发跟随逻辑
3. 循环防御：通过深度计数器限制最大解析层数，拦截循环链接

最终选择在「`namei`获取inode并加锁之后、文件类型校验之前」插入符号链接解析逻辑，选型依据如下：

1. 此时已获取inode的`type`字段，可以准确判断是否为符号链接
2. 此时已持有inode锁，读取inode数据块中的目标路径时，不会出现并发修改导致的数据不一致
3. 解析跳转得到目标inode后，可以直接复用原生后续的类型校验、fd分配等全部逻辑，无需重复编写代码

#### 3.4.3 符号链接循环解析逻辑设计

1. **循环结构选型**：采用while循环结构而非单次if判断，支持多层嵌套的符号链接解析。循环的终止条件为「当前inode不是符号链接」或「设置了O_NOFOLLOW标志」。
2. **循环入口条件**：设置为 `ip->type == T_SYMLINK && !(omode & O_NOFOLLOW)`，双条件同时满足才进入解析，确保普通文件、目录、设备文件直接跳过，不影响原有逻辑。
3. **目标路径读取**：复用内核已有的`readi`函数读取符号链接内容，第二个参数传`0`表示缓冲区为内核地址，偏移量传`0`，读取长度传`MAXPATH - 1`，预留终止符位置。
4. **字符串终止符处理**：读取完成后手动补充`\0`终止符。`readi`是纯字节拷贝函数，不会自动补充C字符串终止符，必须根据实际读取字节数手动添加，保证后续`namei`解析合法。
5. **深度限制设计**：循环内维护`depth`计数器，每解析一层自增1，超过10层直接返回错误，防御循环符号链接导致的内核死循环。
6. **inode替换的资源处理顺序**：严格遵循「读取旧inode数据→释放旧inode资源→解析新路径获取新inode→给新inode加锁」的顺序，保证资源不泄漏。
7. **失败路径统一清理**：所有失败分支都遵循「释放inode锁与引用→结束日志事务→返回错误」的顺序，保证资源一致性。

#### 3.4.4 编译错误与结构性缺陷修复

1. **argint返回值编译错误修复**xv6的`argint`返回值类型为`void`，不能写入条件判断表达式。将参数获取逻辑拆分，`argstr`单独做失败判断，`argint`单独调用。

2. **readi参数类型不匹配修复**`readi`第三个参数类型为`uint64`，内核字符指针无法隐式转换。将缓冲区地址强制转换为`uint64`类型传入，符合xv6内核读写内核态缓冲区的标准写法。

3. **结构性野指针缺陷修复**初始版本将`filealloc()`和`fdalloc()`写在非`O_CREATE`的else分支内，导致`O_CREATE`分支执行到文件结构体初始化时出现野指针panic。将文件类型校验、fd分配、结构体初始化等公共逻辑整体移动到if-else分支之外，保证两个分支都能执行到。

#### 3.4.5 实际代码变更

##### （1）参数获取逻辑修复

```c
// 修改前
if((n = argstr(0, path, MAXPATH)) < 0 || argint(1, &omode) < 0)
    return -1;

// 修改后
if((n = argstr(0, path, MAXPATH)) < 0)
    return -1;
argint(1, &omode);
```

##### （2）新增符号链接循环解析逻辑

在`namei`获取inode并加锁后，插入循环解析代码：

```c
int depth = 0;
while(ip->type == T_SYMLINK && !(omode & O_NOFOLLOW)) {
    char target[MAXPATH];
    int sz = readi(ip, 0, (uint64)target, 0, MAXPATH - 1);
    if(sz < 0){
        iunlockput(ip);
        end_op();
        return -1;
    }
    target[sz] = '\0';

    if(++depth > 10){
        iunlockput(ip);
        end_op();
        return -1;
    }
    iunlockput(ip);
    if((ip = namei(target)) == 0){
        end_op();
        return -1;
    }
    ilock(ip);
}
```

##### （3）公共逻辑外移

将原else分支内的文件类型校验、`filealloc`、`fdalloc`代码块整体移动到if-else结构之后，保证`O_CREATE`与普通打开分支都能执行到文件结构体分配逻辑。

### 3.4.6 实现效果

修改完成后，`sys_open`可正确解析单层与多层符号链接，`O_NOFOLLOW`标志可正常阻止链接跟随，循环符号链接会被深度限制拦截，不会引发内核死循环；原有普通文件、目录、设备文件的打开逻辑不受任何影响。编写的`symlinktest`测试程序基础功能与并发场景全部通过。
